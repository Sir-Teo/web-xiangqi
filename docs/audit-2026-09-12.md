## Retain tournament preparation before the first move

A browser reproduction entered players and an event beside a starting-position
note, then erased the note. The game-details editor disappeared and automatic
recovery cleared the study, discarding the tournament details on reload.
The storage reader also rejected a metadata-only game, and the PGN importer
refused the resulting move-free record.

Normalized game details now count as study content for library storage,
automatic recovery and PGN copy/download/import. The collapsed details editor
is available before the first move. Whitespace, unknown fields and malformed
metadata do not create empty recovery prompts. Removing the last note keeps
the remaining details visible and recoverable. Share URLs still carry positions,
lines and notes; they do not carry tournament metadata, so a metadata-only
draft does not enable Copy Link.

The new browser regression failed against the original code, then passed at
1440, 390 and 320px. It exercises save, recovery, library search/load, PGN copy
and download, reimport, empty reset, and horizontal overflow. The phone
screenshot was inspected. Unit regressions cover storage normalization,
recovery and rejecting invalid move text even when PGN headers are present.
TypeScript, lint, all 1,549 unit tests, engine contract and server-header checks
pass. Browser QA is repeated after committing; the broader baseline matrix
uses the previous fixed production build.

## Engine research and priorities

[Pikafish](https://github.com/official-pikafish/Pikafish) is the relevant
Stockfish-derived Xiangqi engine. Its
[UCI documentation](https://github.com/official-pikafish/Pikafish/wiki/UCI-&-Commands)
describes runtime option discovery, setting Hash after Threads, single-PV
search for best performance, and readiness barriers. Its WDL output models
engine self-play, so those figures should not be presented as a beginner's
personal winning probability. The documentation itself lists different MultiPV
maxima in its example and prose; the engine's advertised options are the
appropriate authority for a particular binary.

The current app already uses SIMD, workers, bounded search scheduling and
separate beginner opponents. Raising the thread count blindly is inappropriate:
the configured eight-thread limit depends on the twelve-worker WASM pool.
The local NNUE file is about 51 MiB, whereas each WASM core is under 700 KiB.
Cold-start transfer and peak memory deserve separate measurements from search
throughput. Browser battery and thermal behavior still need physical devices.

Professional priorities to investigate next: larger study/library capacity,
incremental persistence and indexing, full tournament-header round-trips,
repertoire practice across variations, and reliable saved analysis provenance.
Beginner priorities: clear explanations of threats and evaluation uncertainty,
progressive access to engine controls, and completing play/training workflows
on short screens with enlarged text. Existing features and regressions should
be extended before adding duplicate controls.
