# Continuous improvement audit — September 11, 2026

This pass continues the earlier audits. It does **not** certify every file or
claim that the app already covers every professional workflow. The repository
contains over 300 tracked files; the application shell alone started at 7,430 lines.

Deletion snapshots now also check game identity. Previously, loading another
game with the same starting FEN left the old Undo action available; browser QA
confirmed that clicking it replaced the newly loaded board with the previous
study. Undo now clears on load/reset and the restore operation itself rejects
snapshots from another game. Desktop/phone checks preserve ordinary deletion
recovery and cover both same-root library loads and New Game.

Autosave now checks the recovery reader's move and tree limits before reporting
success. A 1,025-move snapshot previously returned `saved` while its own reader
returned `null`; the 2 MB byte ceiling did not catch a record of only 7,289 JSON
characters. Oversized studies now show the existing recovery warning and PGN
download action. Invalid snapshots are also rejected before writing. Tests cover
the exact limit, branches outside the current line, and returning to recoverable
size after pruning. Larger study capacity remains an open product requirement.

The recovery warning's phone actions were below the 44-pixel touch target and
the portrait warning overlapped the move-navigation strip. Recovery and Undo
actions now have 44-pixel minimum touch dimensions, and portrait recovery
warnings clear the strip. Browser checks measure action bounds and the gap,
verify no horizontal overflow at 320/390 pixels, and complete the recovery flow.

The serializer now uses an explicit traversal stack and one ancestry set instead
of copying the whole ancestor path at every move. Shared subtrees still appear
under every branch; existing cycle behavior, child ordering, normalized notes,
and immutable inputs are retained. A 10,000-node helper stress test no longer
exhausts the call stack. This does not raise the app's 1,024-move storage limit.

The focused tests are `scripts/test-cloud-pv-browser.cjs`,
`scripts/test-search-queue-browser.cjs`, `scripts/test-wdl-freshness-browser.cjs`,
`scripts/test-engine-position-browser.cjs`, `scripts/test-engine-line-browser.cjs`,
`scripts/test-unicode-share-browser.cjs`, and `scripts/test-engine-boot-race-browser.cjs`,
all included in `npm run test:ui:audit`.
Cloud responses are intercepted, making these checks independent of the service.
The queue test uses controlled UCI messages and the browser clock; engine
integration is covered separately by smoke/parity tests and production QA.

Ordinary Go Deep results also need explicit retention after completion. The
browser reproduction replaced a depth-28 result with depth-8 live analysis on
return from a hidden tab. Completed manual searches now have a distinct stage
owned by the current request; their score, PV, and WDL survive tab changes.
Navigation and ordinary live-search pause/resume still invalidate or refresh
results. An immediate replacement engine exposed a second race: React batched
unready/ready into an unchanged boolean, leaving old PVs and skipping fresh
analysis and option restoration. The engine now publishes its ready session
identity, so a new session invalidates old results and reapplies options even
when no unready frame rendered. Extra `readyok` replies within the same session
do not restart analysis. Browser tests assert fresh commands, MultiPV/WDL
restoration, the current position history, and cleared restart notices. `scripts/test-deep-result-browser.cjs` covers completion while
hidden, completion before hiding, stopped infinite searches, and invalidation
at 1440/390/320px. Set `XIANGQI_QA_REAL_DEEP=1` for the bounded real-engine check.

Candidate-line copying now honors the shared clipboard helper's boolean result.
Previously, denial of both the Clipboard API and selection fallback still
showed “Copied” because the component only checked for thrown exceptions.
Browser regressions cover denial, honest failure feedback, and a successful
retry at 1440/390/320px.

Normal PGN import now retains written notes on nested variations. Previously,
the coordinate tree reader stripped comments and the separate annotation pass
restored only the main line; a six-move browser reproduction retained all moves
but lost four branch notes. The tree reader now consumes comments alongside
move tokens, so comment coordinates and parentheses cannot enter the move tree.
Consecutive brace/semicolon notes are combined within the existing 500-character
limit. Saved analysis metadata uses the same branch-aware pass instead of text
markers. Regressions cover paste, file export/import, library save, recovery, and
narrow layouts. A preface before a variation's first move is not assigned to its
parent; position-preface storage remains unsupported. The normal importer now
also retains variation evaluations and the three supported quality glyphs.

The normal review importer also rejected positive signs, decimal shorthand and
depth-suffixed evaluations such as `[%eval +0.42,18]`, which the
[python-chess reference parser](https://python-chess.readthedocs.io/en/latest/_modules/chess/pgn.html)
accepts. Those scores now import, preserving Red perspective and signed mate
zero. The first valid evaluation in a comment wins across both score kinds;
an unrelated later mate no longer takes priority over the first centipawn score.
Unrepresentable mate distances and unsafe numeric values are rejected. This
compatibility fix is followed by move-level persistence: imported evaluations,
their supplied depths, and supported quality glyphs now survive library save,
autosave recovery, backups, share links within their size limit, and PGN export,
including annotations on variations and unbranched lines with no written notes.
These fields do not fabricate a completed review or claim an engine identity.
Ordinary live readings remain transient unless they replace an already durable
annotation. New evaluation writes clear the previous depth when the new search
does not supply one, even when the numerical score stays the same. A completed
review replaces move-quality annotations only on the line it evaluated.
The collection importer continues its stated policy of preserving engine
annotations as note text. Arbitrary NAGs outside the supported quality mapping
remain an open normal-import limitation.

This exposed another engine boundary bug: `bestmove` without any preceding
score supplied the default numeric zero to the application. A controlled browser
reproduction changed a visited variation's PGN to `[%eval 0.00]` despite the
engine having said nothing about its evaluation. Completion now carries an
explicit score-presence flag. Scoreless live searches preserve the old value;
scoreless reviews stop with an explanation instead of grading a fabricated zero.
Browser checks cover depth invalidation, scoreless-review cancellation,
save/reload/share, variation scores, and PGN re-export at all three widths.

## Review cancellation and annotation ownership

A browser regression demonstrated that even a scoreless review erased a
`$4` quality mark on an imported sibling variation. Starting review cleared
all qualities globally; successful intermediate searches also wrote scores and
recommendations into the study, so cancellation left a partial review behind.
Review now stages scores and recommended lines privately, applying them together
only on completion. Cancelling, a scoreless result, or worker failure discards
those staged results. A rerun retains the previous completed summary for saving
and autosave, and cancellation restores that summary in the review panel.
Clearing a completed review touches only its reviewed line, and clears its full
recommended line along with its best move. Sibling annotations remain intact.
The running panel explains when scores change and what Cancel preserves.

This also removes per-position recommendation writes and the timed score batch
writes that repeatedly copied the move tree and invalidated storage snapshots.
This is a reduction in application work, not a measured engine speedup. Review
progress still updates per position; the driver explicitly observes completed
steps so an immediately returning engine cannot stall the queue when React
batches searching and idle into one render.

## Live score comparisons and remaining score-type work

The pinned [Pikafish score formatter](https://github.com/official-pikafish/Pikafish/blob/beeca5cc785ceb2026c5f9248f6e057573b12906/src/uci.cpp)
outputs separate `cp` and `mate` kinds; the [Stockfish UCI reference][uci]
also demonstrates typed scores, bounds, and sequential MultiPV updates. The
live line score badges already kept the kind, but the comparison labels inferred
it from the numeric mate-sentinel range. Thus `cp 29950` could be labelled
"Mate in 50", despite its badge displaying a centipawn evaluation. A unit
regression additionally reproduced losing mate zero labelled "Mate in 0".
Comparisons now read the engine's score kind, retain negative zero, and avoid
subtracting a mate sentinel from an ordinary score. A secondary reading above
the current first line says "ahead" instead of "Equal"; a comparison involving
a bound says "Not exact" with explanatory hover text. These are live readings,
not claims that all slots have finished the same search depth.

A controlled browser workflow checks both sides to move, Red-perspective score
badges, spoken line descriptions, bounds, and layout at 1440/390/320 pixels.
It is part of the three-browser regression matrix.

The same ambiguity also corrupted persisted annotations: a direct reproduction
imported `[%eval 200.00]` as `20000`, displayed `+M10000`, and exported
`[%eval #10000]`. Move evaluations now retain a score-kind override wherever a
centipawn value overlaps the legacy mate range. This sparse representation
preserves the existing encoding for other values and avoids adding redundant
metadata to every ordinary move. The override travels through PGN main lines
and variations, storage/share normalization, engine completion, review annotations
and key moments (including their root-position evaluation), graph points/extrema,
library summaries, and PGN export. Replacing an evaluation replaces its kind even
when the numeric value is identical. A rejected engine bound cannot change the
kind of the exact score being retained.

Unit checks cover normalization, same-number kind replacement, root and move
review kinds, and a mixed cp/mate PGN → storage → share → PGN round-trip.
The browser workflow also checks graph and library labels, completed review
labels, reload recovery, share loading, and same-number live-engine replacement
at all three widths. Existing records that already lost their score kind retain
their legacy interpretation; the original PGN must be reimported or the position
reanalyzed to recover the intended type. No threshold change or clamping of
large imported numeric evaluations is used to hide that ambiguity.

## Position editor keyboard navigation

The editor exposed all 90 squares as separate Tab stops and did not move
between them with arrow keys. It now has one board Tab stop, arrow navigation,
Home/End for the current rank, and Ctrl+Home/End for the board's corners.
Native Enter/Space activation places or removes a piece once. Grid, row, and
cell semantics plus a short keyboard instruction describe the interaction.
This follows the [W3C keyboard convention](https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/)
of using Tab between components and arrows within a composite component.

The shared dialog trap now excludes negative Tab indices, disabled/inert
controls, and descendants of hidden containers; it includes native disclosure
summaries. Wrapping focus lets the dialog scroll to the destination. The
regression checks editing, boundaries, returning focus after Escape, hidden
controls, and visible focus at desktop, phone, short, and landscape sizes.
This is automated browser coverage, not a complete assistive-technology audit.

## Performance findings

The library explorer now reuses its worker across saved-library changes and
keeps only the newest pending query while an index build or lookup is running.
Previously, every new library array terminated and replaced the worker. A
controlled browser test holding the first reply measured 21 workers and 21
build requests for 21 library versions before the change, versus one worker
and two builds after it. These are work counts, not a wall-clock speedup claim.
The same replacement path produced a WebKit development-server module-load
error after saving a game; tracing identified the index worker, and the native
WebKit reproduction passes with worker reuse.

Replies carry request IDs so old or duplicate replies cannot finish a newer
query. Clearing the library releases the existing index; empty startup creates
no worker. Failure remains visible without damaging saved games, and a later
library update can start a replacement. Controlled coverage checks coalescing,
stale replies, emptying/repopulating, and abandoned-worker errors at 1440, 390,
and 320 pixels. Native-worker coverage verifies legal continuations and board
navigation before index loading completes. Both workflows are included in the
Chromium, WebKit, and Firefox matrix.

- **Avoid regex backtracking in PGN notes.** Repeated unclosed `[%` annotation
  commands inside a valid comment made the normal importer's note parser rescan
  the remaining text at every opener. A 198,012-character regression took
  6,523 ms before the fix on this machine. Reusing the linear delimiter scanner
  preserves the same bounded note and moves; `node scripts/bench-pgn-comments.mjs`
  now measures a 0.250 ms median / 0.321 ms p95 for that input after five warmups
  and twenty samples. This is isolated parsing of a pathological note, not a
  typical-game or device-speed claim. The browser regression imports the full
  note, navigates to its move, saves it, and checks 1440/390/320px layouts.
- **Avoid wasted searches first.** The confirmed scheduling race is fixed.
  Continue examining search ownership and stop/restart boundaries before changing
  engine budgets. Preserve the full move history when analyzing repetitions.
- **Avoid repeated tree copies.** On this development machine, adding 64 moves
  to an 800-move tree took a median 4.73 ms (p95 5.11 ms) with the old insertion
  algorithm versus 0.25 ms (p95 0.30 ms) with the shared helper. The benchmark
  warmed both implementations, interleaved 50 runs, and checked equal output.
  This isolated Node/Vite JavaScript measurement excludes rendering, engine
  search, and storage; it is not a whole-interaction or phone speed claim.
- **Serialize ancestry once.** Run `node scripts/bench-study-serialization.mjs`
  to compare the former algorithm with the current serializer. On this machine,
  a 1,024-move annotated chain changed from a 1.758 ms median / 2.229 ms p95 to
  0.096 ms / 0.154 ms. The 50 interleaved samples follow warmup and an equal-output
  check. This excludes JSON encoding, storage writes, browser rendering, and
  engine work. The performance gain is in assembling the tree snapshot.
- **MultiPV costs depth.** [Stockfish's UCI documentation][uci] recommends one
  line for maximum performance. The pinned Pikafish `search.cpp` performs a root
  search for each PV. The app already uses one line outside detailed analysis;
  increasing defaults would trade depth for alternatives. Benchmark fixed-time
  depth and responsiveness with 1/3/5 lines before changing the existing choice.
- **Coalesce progress before crossing the worker boundary.** The real network
  download produced a median 4,085 callbacks versus 52 after coalescing, about
  98.7% fewer messages. Five interleaved Chromium samples per implementation used
  fresh contexts, the real 53,719,310-byte network, single-SIMD, one thread, and
  16 MB hash; each completed a depth-one search. Median ready times were 935.1
  and 931.1 ms, effectively unchanged in this small local experiment. This is
  a reduction in queued work, not evidence of faster engine search, rendering,
  or phone startup. Initial/completion/reset reports and byte integrity remain
  covered, including unknown and encoded content lengths. Reproduce with
  `git show 8600929:templates/pikafish.js > /tmp/xiangqi-progress-baseline.js`
  followed by `node scripts/bench-progress-browser.cjs /tmp/xiangqi-progress-baseline.js`.
- **Ordinary compression will not shrink the weights.** The shipped NNUE file
  is 53,719,310 bytes. Node gzip produces 53,732,472 bytes; Brotli quality 4
  produces 53,719,450. Both are slightly larger. Prioritize reliable versioned
  reuse of matching engine/network assets, and investigate smaller compatible
  networks only with strength and parity validation.
- **PGN export is not yet a demonstrated responsiveness bottleneck.**
  `node scripts/bench-pgn-export.mjs` warms ten runs, checks the exported move
  sequence, and times fifty annotated straight-line exports at 128/512/1,024
  plies. On this arm64 macOS machine with Node 26.7.0, median times were
  0.051/0.561/1.993 ms; the 1,024-ply p95 was 2.586 ms. This measures text
  generation only, excluding rendering, clipboard/download work, and engine
  search. The exporter still copies ancestry sets recursively, so revisit its
  scaling before raising study limits. These local timings do not establish a
  phone bottleneck or justify claiming a noticeable UI speedup from a rewrite.
- **Frontend structure remains worth investigating.** The production main
  JavaScript bundle is about 473 kB / 145 kB gzip. Splitting optional study and
  import surfaces could reduce first-load parsing and simplify maintenance.
  The large source file is evidence of complexity, not proof of slow frames.
  Use production traces before claiming a speed improvement.
- **Device behavior still needs direct evidence.** Chromium viewport tests
  verify layout, not phone thermal throttling, memory pressure, touch hardware,
  Safari, or battery drain. Do not tune mobile thread/hash defaults from desktop
  viewport emulation alone.

## Feature priorities

1. **Analyze selected candidates — implemented.** Engine → Compare offers one
   to five legal moves, with bounded, Go Deep, and infinite searches. The full
   position command retains move history, and `searchmoves` comes last for the
   pinned Pikafish parser. Results identify the selected set and Red perspective;
   they cannot become the unrestricted evaluation, review grade, or saved score.
   Keep/copy/follow reuse study continuations. A
   [Stockfish maintainer explains][searchmoves] why restricted scores may differ.
   Native move selection includes piece names and squares for beginners.
   Browser coverage checks 1440/390/320px, legal choices and the five-move limit,
   history, MultiPV, score isolation, saving both branches without moving the
   cursor, editing, stopping infinite analysis, replay, and focus restoration.
   A delayed Stop acknowledgement regression verifies that the toolbar, D key,
   and command palette also cancel a queued deep search; previously it started
   after cancellation. A subsequent background-completion check exposed lost
   results when a deep search finished while hidden. Completed comparisons and
   explicitly requested deep searches now retain their results across tab
   changes; ordinary running comparisons still stop when hidden. Browser tests
   cover each transition and delayed stop acknowledgements.
   Run `XIANGQI_QA_REAL_CANDIDATES=1` with `scripts/test-candidate-browser.cjs`
   for an additional real-engine workflow. Kept lines retain the candidate set in their saved analysis snapshot; active
   comparison sets remain temporary and reset on position changes.
2. **Persist useful analysis as study variations — implemented.** Kept lines
   now store a separate snapshot of the position before their first move: full
   engine position command/history, Red-positive score and score kind, depth,
   bound status, MultiPV/candidate scope, capture time, reported UCI engine name,
   runtime variant, effective threads, and hash size. The Tree panel exposes it
   without replacing current evaluations or review grades. Updating a snapshot
   is explicit, preserves notes, and reuses the existing moves. Library saves,
   autosave, JSON backups, and size-bounded share links preserve the data.
   A custom `[%xqanalysis ...]` PGN comment round-trips through this app's import
   paths; other tools may ignore it. Mismatched source histories and malformed
   metadata are dropped without discarding legal study moves. Exact engine and
   network artifact hashes remain future provenance work. Score formatting also
   preserves the side of mate in zero instead of treating negative zero as Red.
   `scripts/test-study-analysis-browser.cjs` checks capture/update, save/share,
   PGN import/export, reload, source-history rejection, and narrow layouts at
   1440, 390, and 320 CSS pixels. Set `XIANGQI_QA_REAL_ANALYSIS=1` for additional
   desktop and touch-viewport checks with the shipped engine. These are browser
   viewport checks on macOS, not measurements on physical phones.
   Follow-up: the initial snapshot validator stopped at depth 128, although
   the pinned [Pikafish types](https://github.com/official-pikafish/Pikafish/blob/beeca5cc785ceb2026c5f9248f6e057573b12906/src/types.h)
   define `MAX_PLY` as 246 and its search loop allows depth 245. The bounded
   storage field now accepts depths through 256 without changing search limits.
   A regression rejects the old validator and verifies deep snapshot retention.
   Browser coverage also checks that updating such a snapshot preserves notes.
   The first full browser matrix exposed a timing dependency in two share-link
   tests: a sender autosave could open the recipient's recovery dialog and block
   command shortcuts. The tests now wait for autosave and explicitly choose
   “Keep the link's game,” exercising the existing recovery flow consistently.
   The note assertion waits for the selected move's editor value: Chromium can
   return the previous value before the selection effect updates the draft.
   Diagnostic runs confirmed the note remained intact at all three widths.
3. **Guided tactical lessons and spaced mistake practice.** The app already
   has first-move help, letter pieces, an opponent ladder, and review-based
   mistake drills. Add curated lessons for horse legs, cannon screens,
   flying generals, and stalemate losses, plus progress across practice sessions.
   [PyChess][pychess] provides a useful reference for the combination of puzzles,
   analysis, editor, import/export, and multilingual learning.
4. **Larger study libraries.** Storage currently caps the library at 500 games
   and 3,000,000 JSON characters. A professional preparation corpus will exceed
   these limits. Plan an IndexedDB migration with atomic writes, metadata
   indexing, incremental explorer updates, and recoverable backups; simply
   raising the synchronous localStorage limits would increase stalls and quota
   failures.
5. **Chinese interface localization.** Chinese notation is implemented; an
   English-only interface still creates friction for many Xiangqi players.
   Extract product strings with native-language review and verify longer labels,
   narrow screens, focus order, and screen-reader announcements.

Pikafish is already a [Stockfish-derived Xiangqi engine][pikafish]. Ordinary
Stockfish is a protocol and architecture reference here, not a replacement
engine. Upstream findings must be checked against the pinned local revision
`beeca5cc785ceb2026c5f9248f6e057573b12906` before being used in the shipped WASM.
